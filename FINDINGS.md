# Mathematical findings

This file records the main reusable conclusions for `PROBLEM.md`.

## 1. Graph and potential formulation

Treat A-columns as graph vertices and rows as colored edges. The right kernel
of `A` is generated by connected-component indicators, and `ker(A.T)` is the
cycle space. Constraint 1 says that edge-color parity maps the cycle space
isomorphically onto the target code `C`.

For a parity-check matrix `H` with `ker(H)=C`, write `h_j` for column `j`.
Every graph vertex has a syndrome potential `x_v`, and an edge of color `j`
between `u,v` satisfies

```text
x_u + x_v = h_j.
```

Constraint 2 is equivalent to requiring every same-component potential
difference to have a B-space representative of weight at most two.

## 2. Exact feasibility criterion

A nonzero target code is feasible if and only if it is spanned by codewords of
weight at most five.

### Necessity

Fix a root in every graph component. By Constraint 2, choose for each vertex
`v` a vector `l_v` of weight at most two representing its potential relative
to the root. For an edge `e=uv` of color `j`,

```text
c_e = e_j + l_u + l_v
```

has zero syndrome and is therefore in `C`. Its weight is at most five.

For a zero-A edge combination, every `l_v` occurs an even number of times and
cancels. Its B-image is consequently a sum of the low-weight words `c_e`.
Constraint 1 says these B-images span `C`, so the weight-at-most-five words must
span `C`.

### Sufficiency

If weight-at-most-five words span `C`, choose an independent basis from them.
Represent each basis word by a separate graph-cycle component:

- weight 2: two parallel edges;
- weight 3: triangle;
- weight 4: four-cycle;
- weight 5: five-cycle;
- weight 1: a triangle whose three edges all have that color.

Every component has diameter at most two, its unique cycle maps to the chosen
basis word, and the components' cycle images form a basis of `C`. Thus all
constraints hold.

This settles feasibility completely; the remaining hard problem is minimizing
the number of rows.

## 3. Consequences

- Minimum target distance `d_T >= 6` implies infeasibility immediately.
- Minimum distance below six is not sufficient. The low-weight words must span
  the entire target.
- The `[23,12,7]` Golay target is infeasible.
- The twice-punctured `[21,12,5]` Golay target is infeasible because its
  weight-five words span only dimension 10 instead of 12.
- The `[[20,2,6]]` phantom-code target is infeasible because its weight-at-most-
  five words span only dimension 5 instead of 11.

## 4. Why multiple A-components help optimization

Constraint 2 applies only to pairs of vertices in the same component. Splitting
potential sets into components avoids incompatible cross-pairs. Their cycle
images can still cooperate globally because Constraint 1 concerns the sum of
all component cycle spaces.

For component `i`, let `d_i=m_i-1` be its forest rank and let `D_i` be its cycle
image subspace. If the `D_i` together span the `r`-dimensional target, an
independent selection uses

```text
k = r + sum_i d_i.
```

Thus optimization can be viewed as a minimum-cost subspace-cover problem over
compatible potential components. This viewpoint improved the distance-four
planar surface-code result from 40 rows to 31 rows.

## 5. Planar surface-code family

For the standard planar family

```text
[[L^2+(L-1)^2, 1, L]],
```

the logical-zero target consists of the Z-stabilizer space plus one logical Z.
Boundary stabilizers keep `d_T=3`, but this does not imply feasibility for all
`L`.

- For `L<=5`, Z checks have weight at most four and logical Z has weight `L`, so
  weight-at-most-five words span the target: the instances are feasible.
- For `L>=6`, every weight-at-most-five target word is a stabilizer because a
  nontrivial logical Z has weight at least `L`. They span only the stabilizer
  space, which has codimension one in the target. Hence every `L>=6` member is
  infeasible.

Current optimization results:

| L | n | r | result |
|---:|---:|---:|---:|
| 2 | 5 | 3 | `k_min = 5` |
| 3 | 13 | 7 | `k_min = 13` |
| 4 | 25 | 13 | `25 <= k_min <= 31` |
| 5 | 41 | 21 | `41 <= k_min <= 69` |
| >=6 | `L^2+(L-1)^2` | `L(L-1)+1` | infeasible |

There is therefore no large-L finite scaling for logical-zero preparation under
the stated constraints: feasibility terminates at distance five.

## 6. Surface target with logical Z omitted

If the logical-Z row is deliberately omitted, the target is only the
`L(L-1)`-dimensional Z-stabilizer space. This no longer fixes the logical qubit
to `|0>`, but every target basis row then has weight three or four, so the
instances are feasible for every `L`.

Removing a target row does not necessarily reduce the optimized `k`: Constraint
2 may correct a path by adding any target codeword, so a larger target provides
more low-weight representatives. Removing logical Z takes those corrections
away even though it lowers `r` by one. This is why the current stabilizer-only
bounds can be worse than the corresponding logical-zero bounds.

For `L>=4`, pair each of the `2(L-1)` triangular boundary checks with a
compatible square check. Each triangle/square theta component uses six rows,
one fewer than separate cycles. Leave the remaining `(L-1)(L-4)` square checks
as four-cycles. The same row-count formula is attained by a special
multi-component construction at `L=3`:

```text
r = L(L-1)
k <= 4(L-1)^2
m = 2(L-1)(2L-3)
number of A-components = (L-1)(L-2).
```

Every physical coordinate is active, giving the lower bound

```text
2L^2-2L+1 <= k_min <= 4(L-1)^2.
```

Thus `k_min = Theta(L^2)` for the stabilizer-only target, with the current
asymptotic upper bound approximately twice the support lower bound. Concrete
values are:

| L | n | r | current bounds |
|---:|---:|---:|---:|
| 2 | 5 | 2 | `k_min = 5` |
| 3 | 13 | 6 | `13 <= k_min <= 16` |
| 4 | 25 | 12 | `25 <= k_min <= 36` |
| 5 | 41 | 20 | `41 <= k_min <= 64` |
| 6 | 61 | 30 | `61 <= k_min <= 100` |
| 7 | 85 | 42 | `85 <= k_min <= 144` |
